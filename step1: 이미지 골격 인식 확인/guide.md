# 골격(구조 측량) 단계 평가 가이드

복잡한 표 이미지 → MD/HTML 파이프라인에서, **골격 파악 하위 단계만 격리해 이 모델이 정말 뛰어난지** 검증하기 위한 가이드. 단일 요청이 최종 목표이므로, 여기서 검증된 부분만 모델에 맡기고 나머지는 코드/보강으로 넘기는 분기점을 찾는 것이 목적이다.

---

## 0. 무엇을 "골격"으로 정의하는가

좌표·픽셀 없이, 다음의 **거친 관계·개수 정보**만을 골격으로 본다.

- `total_columns` — 전체 열 수 (병합 반영 후 정규 열 수)
- `header_levels` — 헤더 단(계층) 수
- `header_spans` — 어떤 상위 헤더가 어떤 하위 헤더들을 묶는가
- `body_row_count` — 본문 행 수
- `merges` — 병합이 일어난 구획의 (앵커 라벨, 방향, 덮는 칸 수)

이 단계에서는 **셀 내용 전체 전사는 하지 않는다.** 앵커로 쓸 라벨 텍스트만 참조한다.

---

## 1. 평가 설계 원칙

1. **계량 금지.** 좌표·박스·픽셀·"몇 번째 픽셀"을 일절 요구하지 않는다. (가설 1: 양자화 좌표는 약점)
2. **텍스트 앵커 강제.** 위치는 항상 읽을 수 있는 라벨 기준으로만 지정. 빈 칸/병합 칸은 이웃 라벨로 상대 지정.
3. **개수·관계로만 질의.** 가능하면 "몇 번째 열"(서수)도 피하고, "이 헤더가 묶는 하위 열의 개수"처럼 개수·관계로 변환.
4. **구조화 출력 강제.** JSON 스키마로 받아 기계적으로 채점 가능하게.
5. **대조군 포함.** 같은 골격을 (a) 관계 앵커 방식과 (b) 좌표·서수 방식 두 가지로 물어, 가설이 *내 모델·내 데이터*에서 실제로 성립하는지 본다.

---

## 2. 테스트 프롬프트

### 2-A. 주 조건 — 관계 앵커 골격 질의

```
첨부한 이미지에는 표가 하나 있다. 이 표의 "구조 골격"만 분석하라.

규칙:
- 픽셀 위치, 좌표, 바운딩 박스를 절대 보고하지 마라.
- 위치는 항상 읽을 수 있는 텍스트 라벨을 기준점으로만 지정하라.
- 병합/빈 칸은 가장 가까운 읽을 수 있는 이웃 라벨을 기준으로 가리켜라.
- 셀 내용을 전부 옮기지 마라. 구조에 필요한 라벨만 참조하라.

다음 JSON만 출력하라(설명·서론 없이):
{
  "total_columns": <int>,                  // 병합 반영 후 정규 열 수
  "header_levels": <int>,                  // 헤더 단(계층) 수
  "header_spans": [                        // 다단 헤더가 없으면 빈 배열
    {"parent_label": "<상위 헤더 텍스트>", "covers": ["<하위1>", "<하위2>"]}
  ],
  "body_row_count": <int>,                 // 헤더 제외 본문 행 수
  "merges": [
    {"anchor_label": "<병합 셀의 텍스트 또는 이웃 기준>",
     "direction": "rows" | "columns",
     "span_count": <int>}                  // 덮는 칸 수
  ]
}

출력 전 자가검증: 병합을 모두 반영했다는 가정 하에, 모든 본문 행은
total_columns 와 동일한 칸 수로 해소되어야 한다. 어긋나면 다시 점검하라.
```

### 2-B. 대조군 — 좌표·서수 골격 질의 (약할 것으로 예상)

```
첨부한 표의 구조를 좌표로 보고하라.
각 헤더 셀과 본문 첫 행의 각 셀에 대해:
{"text": "...", "row_index": <int>, "col_index": <int>,
 "box_2d": [ymin, xmin, ymax, xmax]}  // 0-1000 정규화
```

두 조건의 결과를 같은 정답에 대해 비교한다. 주 조건이 대조군보다 안정적·정확하면,
"관계로 묻고 계량은 빼라"는 설계 원칙이 내 환경에서 검증된 것이다.

---

## 3. 테스트 세트 — 난이도 사다리

각 난이도마다 표 이미지 3~5장을 준비하고, 손으로 정답(아래 4절 형식)을 단다.
목적은 **정확도가 어디서부터 무너지는지 경계 찾기**.

| 레벨 | 특성 | 기대 |
|------|------|------|
| L0 | 괘선 있는 단순 격자, 병합 없음, 단일 헤더 | 거의 완벽 |
| L1 | 행 머리글 병합(카테고리가 여러 행을 덮음) | 양호 |
| L2 | 다단계 열 헤더(colspan) | 약간 흔들림 |
| L3 | 무괘선/희미한 선, 병합 없음 | 열 수 추정에서 오차 시작 |
| L4 | 병합 + 다단 헤더 + 무괘선 결합(현실적 난표) | 무너지는 지점 |

---

## 4. 정답 주석 형식

각 이미지에 대해 사람이 다음을 라벨링한다(주 조건 JSON과 동일 필드).

```
total_columns, header_levels, header_spans(목록), body_row_count, merges(목록)
```

---

## 5. 측정 지표

### 지표 1 — 속성별 정확도 (정답 대비, temperature 0)

올-오어-낫싱이 아니라 **속성별로** 채점한다.

- `total_columns` 정확 일치(0/1)
- `header_levels` 정확 일치(0/1)
- `header_spans` — 집합 단위 F1(올바르게 묶은 비율)
- `body_row_count` 정확 일치, 또는 |오차| 기록(off-by-one인지)
- `merges` — 병합 항목 단위 정밀도/재현율

### 지표 2 — 자가 일관성 / 출력 안정성 (정답 불필요)

골격은 저엔트로피 정보 → **여러 번 물어도 답이 흔들리지 않아야 정상**이라는 가설을 직접 검증.

- 같은 이미지·같은 주 프롬프트를 K회(예: 5) 샘플(temperature 0.3~0.5 권장).
- 각 스칼라 필드의 최빈값과 **일치율**(K개 중 다수가 동의한 비율)을 계산.
- 일치율이 낮으면(예: <0.8) → 그 속성은 모델이 *확신 없이 추측* 중이라는 적신호.

> 정답 라벨링 비용이 큰 초기 단계에서, 지표 2는 정답 없이 대규모로 돌릴 수 있어
> 1차 스크리닝에 특히 유용하다.

### 지표 3 — 관계 vs 좌표 델타 (A/B)

같은 정답에 대해 2-A와 2-B의 정확도 차이. 양(+)이면 설계 원칙 검증.

### 지표 4 — 오류 유형 태깅

틀렸을 때 패턴을 분류한다. 이 패턴이 곧 "코드로 넘길 부분"을 알려준다.

- 열 수 off-by-one (보통 병합/무괘선에서)
- 병합 누락 / 과검출
- 헤더 단 수 환각
- 서수 혼동(“몇 번째 열”을 끌어들이면 어긋남)

---

## 6. 결과 해석 & 분기 규칙

- **정확도 高 + 일관성 高** 인 속성·난이도 → 단일 요청 버전에서 **모델에 맡긴다.**
- **무너지기 시작하는 레벨** → 그 경계가 "모델 신뢰 ↔ 코드/재질의 보강"의 분기점.
- 보강 방향: 깨진 속성을 좌표가 아니라 **관계 재질의**(예: "1열에서 위→아래로 서로 다른 라벨과 각 라벨이 덮는 행 수를 나열")로 다시 묻거나, 코드로 검산.
- **지표 3이 양(+)** 으로 안정적이면, 최종 단일 프롬프트를 관계 앵커 중심으로 설계한다.

---

## 7. 실무 주의

- **이미지 해상도:** 셀 글자가 읽힐 정도는 유지. 과도하게 축소하면 앵커 텍스트가 깨져 골격까지 흔들린다. 매우 큰 이미지는 인코더가 타일링하므로 셀 가독성이 우선.
- **thinking/추론 예산:** 추론 모델이므로 골격 단계는 사고를 켜고 충분히 추론하게 둔다.
- **정확도 측정은 temperature 0, 일관성 측정은 temperature>0** 으로 분리.
- **표본 수:** 레벨당 이미지 3~5장 × K=5 샘플이면 1차 경향 파악에 충분.
- 한 응답에 표가 여러 개면 골격 평가가 오염되므로, 테스트 단계에서는 **표 1개 이미지**로 격리.

---

## 8. 한 줄 요약

골격은 저주파·저엔트로피·관계적 정보라 모델의 강점에 올라탄다. **계량을 빼고 관계·개수만 물어, 정답 정확도와 호출 간 일관성을 동시에 측정**하면, 이 모델이 골격 단계에 실제로 뛰어난지와 *어디서 무너지는지*를 정량적으로 확인할 수 있다.
