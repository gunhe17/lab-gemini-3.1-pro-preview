# Gemini 3.1 Pro Preview: 복잡한 다중 테이블 문서 인식 분석

> 모델의 학습 및 추론 메커니즘을 분해하여, 중첩·병합 테이블 인식 문제의 원인과 해결 방향을 도출한 정리 문서.

---

## 0. 모델 식별 (Model Identification)

- 공식 모델 ID (Identifier): `gemini-3.1-pro-preview`
- `gemini-3-pro-preview`는 2026년 3월 26일부로 단종(discontinued). 신규/기존 프로젝트는 3.1로 전환.
- 출시일: 2026년 2월 19일. Gemini 3 Pro 기반의 포인트 버전(point-version) 업데이트.
- 입력 1M 토큰(token) 컨텍스트 윈도우(context window), 출력 64K 토큰.

## 1. 학습 (Training)

### 1.1 아키텍처: Sparse Mixture-of-Experts (희소 전문가 혼합)

- Gemini 3 Pro는 희소 전문가 혼합(sparse Mixture-of-Experts, MoE) 트랜스포머(transformer) 기반, 네이티브 멀티모달(native multimodal) 모델.
- 라우터(router)가 토큰마다 일부 전문가(experts)에게만 라우팅(routing) → 토큰당 일부 파라미터만 활성화.
- 핵심 통찰: **총 모델 용량(capacity)과 토큰당 연산·서빙 비용(serving cost)이 분리(decouple)됨.**
- 부작용: 라우터가 오배정하면 명의가 많아도 잘못된 처리 → 멀쩡한 표를 엉뚱하게 읽는 구조적 뿌리.

비유: 대형 종합병원. 분류 간호사(라우터)가 환자(토큰)를 관련 전문의에게만 보냄.

### 1.2 학습 데이터 및 인프라

- 사전 학습(pre-training) 데이터: 공개 웹 문서, 텍스트, 코드, 이미지, 오디오, 비디오.
- 학습 도구: JAX + ML Pathways, 구글 텐서 처리 장치(Tensor Processing Units, TPU).
- 지식 마감일(knowledge cutoff): 2025년 1월. 최신 정보는 검색 그라운딩(Search Grounding) 필요.

### 1.3 네이티브 멀티모달 (Native Multimodal)

- 텍스트·비전·오디오를 처음부터 함께 학습 → 이중언어 화자에 비유.
- 표 이미지를 "그림 → 글자 번역"의 2단계가 아니라, 모양과 글자를 같은 표현 공간에서 동시 처리.
- 단순 광학 문자 인식(Optical Character Recognition, OCR)을 넘어 구조 재구성 가능의 토대.

## 2. 추론 (Reasoning / Thinking)

### 2.1 동적 사고 (Dynamic Thinking)

- Gemini 3 시리즈는 기본적으로 동적 사고(dynamic thinking)로 추론.
- 답하기 전 "속으로 생각"하며, 그 과정도 토큰으로 출력됨 → 보이지 않지만 비용이 드는 행위.

### 2.2 thinking_level (사고 수준) 다이얼

| 단계 (Level) | 머릿속에서 일어나는 일 | 비용 영향 |
|---|---|---|
| LOW | 깊은 사고 회로를 끄고 패턴만 빠르게 받아침 | 사고 토큰 70%+ 절감 |
| MEDIUM (신규) | 적당히 숙고, 끝까지 파고들지 않는 균형 모드 | 3.0 Pro의 HIGH와 사실상 동등, 더 저렴 |
| HIGH (기본값) | 어려운 문제를 끝까지 물고 늘어짐 | 복잡 요청 시 사고 토큰 3만+ 소비 가능 |

- `thinking_level`은 `thinking_budget`을 대체(후자는 하위 호환 유지).
- 다이얼은 "최대 상한선"만 정함. 동적 사고이므로 쉬운 질문엔 끝까지 안 씀.

### 2.3 비용 감각 (필수 내재화)

- 사고 토큰(thinking tokens)은 무료 아님 → 출력 토큰과 동일 과금.
- 예: 4,000 사고 + 500 답변 = 4,500 출력 토큰 지불.
- 보이지 않는 사고가 청구서의 대부분을 차지할 수 있음.

### 2.4 사고 서명 (Thought Signatures)

- API 호출 간 추론 컨텍스트 유지 장치. 내부 사고 과정의 암호화된 표현(encrypted representation).
- 비유: 봉인된 메모 봉투. 다음 호출의 자신에게 그대로 되돌려줘야 추론 맥이 이어짐.
- 함수 호출(function calling)에서 누락 시 400 에러. 일반 대화에서도 누락 시 품질 저하.

### 2.5 3.1의 개선

- 향상된 사고, 토큰 효율(token efficiency), 더 근거 있고 사실 일관된(grounded, factually consistent) 경험.
- 이전 대비 평가 실행 최대 15% 개선 보고. 더 적은 출력 토큰으로 동일 품질.
- 의미: 같은 결론에 도달하는 데 더 적은 "혼잣말"만 필요 → 같은 품질을 더 싸게.

### 2.6 정렬 주의 (Alignment Caveat)

- 모델은 "사용자가 만족할 답을 빠르게"라는 학습 목표(training objective)로 훈련됨.
- 결과: 정보 누락 시 빈칸 대신 그럴듯한 값을 추측해 채우는 성향(할루시네이션, hallucination).
- 비유: 모르는 문제를 빈칸 대신 일단 찍는 학생.

## 4. 실험 결과 해석: 질문하기 성공 vs 복제 실패

> 질문에 답하기는 압축(comprehension), 보이는 그대로 옮기기는 무손실 복제(reproduction). 모델은 압축에 최적화됨.

### 4.1 오차 구조: 덧셈 vs 곱셈

- 질문: 관련 셀 하나만 맞으면 성공(고립된 오차, 덧셈).
- 복제: 모든 셀·경계·중첩이 동시에 맞아야 함(곱셈).
- 예: 셀당 98% 정확도, 200셀 → 전체 완벽 확률 = 0.98^200 ≈ 1.7%.

### 4.2 의미(semantic) 작업 vs 기하(geometric) 작업

- 질문하기 = 의미 매칭 → 모델의 강점.
- 복제 = 셀의 행·열 점유, 병합 시작·끝, 중첩 경계의 좌표 수준 파악 → 모델의 약점(공간 정밀도).
- 공식 한계: 위치를 정밀하게 못 찾고 수를 근사치로만 셈.

### 4.3 2D → 1D 직렬화와 표류(drift)

- 모델 출력은 자기회귀(autoregressive): 토큰을 하나씩 좌→우로 생성, 되돌리기·캔버스 없음.
- 2D 격자를 1D 줄로 펴며(linearization) "몇 행 몇 열인가" 추적해야 함.
- 병합 셀의 colspan/rowspan을 한 번 잘못 세면 이후 칸이 전부 밀림(drift, 전파).
- 중첩 표는 재귀(recursion) → 위치 추적 상실 위험 가중.

### 4.4 형식 한계 (Format)

| 출력 형식 | 병합 셀 | 중첩 표 | 복제 적합성 |
|---|---|---|---|
| Markdown | 불가 | 불가 | 낮음 (구조 손실 강제) |
| HTML | 가능 (rowspan/colspan) | 가능 | 중간 (격자 추적 부담 잔존) |

- Markdown 표에는 병합·중첩을 적을 문법 자체가 없음 → 복제 요구 시 실패 예정.

### 4.5 정규화(normalization) 편향

- "그럴듯함" 우선 성향이 복제에선 독으로 작용.
- 불규칙한 원본을 깔끔한 표준 격자로 정규화 → 보기엔 그럴듯하나 원본과 다른, 가장 속기 쉬운 오류.

## 5. 이미지 인식 과정 (Perception)

> 모델은 이미지를 "보는" 게 아니라 잘게 잘라 숫자로 번역해 읽는다.

### 5.1 패치화 (Patchification)

- 이미지를 격자로 잘라 작은 타일(patch) 무더기로 변환. 모자이크 벽화 비유.
- 가는 칸 경계선·작은 글자가 패치 안에서 뭉개지면 처음부터 흐릿하게 입력됨.

### 5.2 비전 인코더 (Vision Encoder)

- 각 패치 → 의미 벡터, 즉 임베딩(embedding)으로 변환.
- 네이티브 멀티모달이므로 시각 벡터가 글자 토큰과 동일한 의미 공간에 놓임 → 사실상 시각 토큰(visual token).

### 5.3 media_resolution (미디어 해상도)

- low / medium / high: 타일 굵기 = 토큰 수 = 비용·지연시간 결정.
- 문서 권고: medium이 최적. 표준 문서는 medium에서 품질 포화, high는 비용만 증가.

### 5.4 가변 길이 토큰화 (Variable Sequence Length)

- 이전 팬 앤 스캔(Pan and Scan)을 대체. 이미지 모양·내용에 따라 토큰 수를 유연 조절.
- 유연해졌어도 "잘라서 번역한다"는 본질은 동일.

### 5.5 종착점 (가장 중요)

- 처리 후 **원본 픽셀과 정밀 좌표는 소멸, 흐릿한 의미 요약만 잔존.**
- "표가 있고 병합 헤더가 있다"는 인상은 강하나, "정확히 3열 2행 점유"는 근사치만 보존.

## 6. HTML 출력 과정 (Derendering)

> HTML은 그림을 "복사"하는 게 아니라, 기억하는 의미를 한 글자씩 "받아쓰기"하는 것.

### 6.1 복사가 아니라 재구성

- 인식 종료 시 손에 남은 건 픽셀이 아니라 의미 요약뿐.
- 디렌더링(derendering): 렌더링(코드→화면)의 화살표를 뒤집어, 그려진 표 → 그것을 만들 코드를 역산.

### 6.2 자기회귀 생성 (Autoregressive)

- `<table>` → `<tr>` → `<td>` 순으로 토큰을 하나씩 생성, 되돌리기 불가.
- 2D 격자를 1D 코드로 펴며 행·열 추적 → rowspan/colspan 오산 시 표 전체 어긋남.

### 6.3 왜 HTML인가

- HTML은 rowspan/colspan, `<td>` 안의 `<table>`을 허용 → 인식한 구조를 손실 없이 담는 그릇.
- HTML은 이해를 살려주는 게 아니라, 이미 이해한 것을 버리지 않게 해주는 그릇.

### 6.4 인식·출력 통합 흐름

```
[원본 이미지]
     │  ① 패치화: 그림을 타일로 자름
     ▼
[패치 무더기] ── ② 비전 인코더: 각 타일 → 의미 벡터(임베딩)
     │            (media_resolution 다이얼이 타일 개수=토큰 수 결정)
     ▼
[시각 토큰] ── 글자 토큰과 같은 공간 → 트랜스포머 + MoE로 이해
     │
     │  ★ 이 지점에서 픽셀·정밀 좌표 소멸, 흐릿한 의미 요약만 잔존
     ▼
[내부 이해] ── ③ 디렌더링: 의미로부터 구조를 역산
     │            토큰 하나씩 자기회귀 생성 (<table><tr><td>...)
     ▼
[HTML 코드]
```

- 결론: 출력 품질의 천장은 **인식 단계(★)에서 이미 결정됨.**

## 7. 좌표 소실의 근본 원인: Vision Encoder 내부

> 비전 인코더는 "이게 무엇인가"를 위해 만들어졌지, "이게 어디 있는가"를 측량하려 만들어진 게 아니다.

### 7.1 엔진은 위치를 타고나지 않음

- 자기 주의(self-attention)는 입력 순서·위치를 본래 모름 → 순열 불변(permutation invariant).
- 비유: 발언 내용은 다 듣되 누가 어디 앉았는지는 신경 안 쓰는 청취자.

### 7.2 좌표 주입: positional encoding (위치 인코딩)

| 구성 요소 | 담는 것 | 비유 |
|---|---|---|
| content embedding (내용 임베딩) | 타일에 뭐가 그려졌나 | 편지 본문 |
| positional encoding (위치 인코딩) | 타일이 격자의 어디인가 | 봉투 주소 |

- 문제의 씨앗: 주소(위치)와 본문(내용)이 **한 종이에 덧셈으로 포개짐.**
- 본문을 가공할수록 같은 종이의 주소도 함께 뭉개질 운명.

### 7.3 self-attention은 "관계"를 계산하지 "거리"를 재지 않음

```
나(패치 A)는 다른 모든 패치에게 묻는다
  → "너는 나와 얼마나 관련 있니?" (내용 유사도로 점수)
  → 관련 높은 패치들의 정보를 가중 평균해서 흡수
```

- 관련도는 주로 내용 유사도로 매겨짐 → 거리는 부차적.
- 흡수 방식이 가중 평균(weighted average) → 평균은 뭉개는 연산 → 날카로운 좌표가 번짐.

### 7.4 층층이 쌓인 평균화 → 과평활화 (Oversmoothing)

- 어텐션 블록을 수십 층 통과. 매 층마다 패치들이 서로 평균내어 섞임.
- 물에 잉크 비유: 1층(선명) → 중간(번짐) → 깊은 층(전체로 퍼져 균질).
- 표현 평활화(representation smoothing) / 과평활화(oversmoothing): 깊은 층에서 패치들이 서로 닮아감.
- 결과: "무엇인가"는 또렷, "어디인가"는 흐릿.

### 7.5 학습 목표도 좌표를 보상하지 않음

- 인코더는 "의미를 맞혀라"로 훈련됨. 좌표 정밀도는 채점 항목에 거의 없음.
- 시험에 안 나오는 부분을 소홀히 하듯, 좌표 보존에 자원을 안 씀.
- 공식 한계("위치 부정확, 수는 근사")는 결함이 아니라 이 설계 철학의 귀결.

### 7.6 좌표 소실 4단계 요약

```
① 엔진(self-attention)은 위치를 본래 모름 (순열 불변)
        │
② 좌표를 '내용과 같은 종이'에 덧셈으로 끼워 넣음 (positional encoding)
        │
③ 어텐션이 의미 유사도 기준 가중 평균으로 정보를 섞음
   → 평균은 뭉개는 연산, 좌표 신호가 번짐
        │
④ 수십 층 반복 → 과평활화(oversmoothing)
   → "무엇인가"는 또렷, "어디인가"는 흐릿
        │
   (게다가 학습 목표가 의미 위주여서 좌표 보존을 보상하지 않음)
```

## 8. 종합 진단과 해결 방향

### 8.1 질문하기 vs 복제 비교표

| 항목 | 질문하기 (성공) | 보이는 그대로 복제 (실패) |
|---|---|---|
| 작업 성격 | 선택적·의미적·압축 | 전수적·기하적·무손실 |
| 필요 능력 | 모델의 강점(의미 이해) | 모델의 약점(공간 정밀도) |
| 오차 구조 | 고립 (덧셈) | 전파·누적 (곱셈) |
| 출력 부담 | 짧은 답 | 2D→1D 직렬화 + 격자 추적 |
| 형식 제약 | 없음 | Markdown은 병합/중첩 표현 불가 |
| 학습 편향 | '그럴듯함'이 도움 | '그럴듯함'이 구조를 왜곡 |

### 8.2 사용자가 쥔 통제 레버 3가지

1. media_resolution (미디어 해상도): 시각 처리 정밀도. 문서는 medium, 글자 깨질 만큼 작으면 high 테스트.
2. thinking_level: 사고 깊이와 비용. 단순 추출 LOW, 관계 추론 MEDIUM+, 결과 나빠지면 HIGH 복귀.
3. 프롬프트(prompt): 추측 성향을 가두는 울타리. "제공된 문서 안에서만 근거를 찾아 추론, 외부 지식 금지"처럼 막연한 금지가 아닌 한정으로.

### 8.3 복제 정확도 개선 방향

- 인식 측: media_resolution 적정화로 ★ 지점의 손실 최소화.
- 출력 측: 출력 형식을 HTML로 고정 → 병합·중첩을 담을 그릇 확보.
- 분업 전략: 한 번에 완벽 복제 대신, (1) 표 구조(골격) 파악 → (2) 셀 내용 채우기로 단계 분리.
- 도구 위임: 좌표 측량이 필요한 부분은 직접 출력 대신 코드 실행(자르고 확대해 재검사) 같은 도구로 이관.

### 분리 원칙: 왜 이렇게 쪼개는가

지난 턴에서 확인한 비대칭이 설계의 근거입니다. 모델은 의미(내용 추출)는 강하고 기하(구조 파악)는 약합니다. 이 둘을 한 프롬프트에 섞으면, 실패했을 때 구조가 틀린 건지 내용이 틀린 건지 알 수 없습니다. 따라서 **강한 축과 약한 축을 물리적으로 분리**해 약한 축만 집중 공략·측정합니다.

또 하나, 측정 없이는 개선도 없습니다. 각 단위마다 합격/불합격을 숫자로 판정할 metric (지표)을 먼저 정의해야 "이 개입이 효과가 있었나"를 답할 수 있습니다.

### 파이프라인 단위 분해 (Pipeline Units)

전체를 5개 단위로 나눕니다. 각 단위는 따로 켜고 끄며 실험할 수 있어야 합니다.

| 단위 | 역할 | 입력 → 출력 | 공략하는 레버 | 합격 신호 |
|---|---|---|---|---|
| U0 입력 정규화 (Conditioning) | 표 영역만 잘라내고 해상도 조정 | 페이지 이미지 → 표 단위 이미지 | media_resolution | 글자가 또렷하게 보이는가 |
| U1 구조 골격 추출 (Structure) | 격자·병합·중첩 골격만 (내용 없이) | 표 이미지 → 빈 셀 HTML | thinking_level=high, 분리 | TEDS-Struct |
| U2 셀 내용 추출 (Content) | 각 셀의 텍스트만 | 표 이미지 → 셀별 텍스트 | thinking_level=low, 행 단위 | 셀 단위 텍스트 정확도 |
| U3 조립 (Assembly) | 골격에 내용을 끼워 넣기 | 골격 + 내용 → 완성 HTML | 코드(모델 아님) | 슬롯 누락 0 |
| U4 검증·복구 (Verify-Repair) | 재렌더 후 원본과 대조 수정 | HTML → 이미지 → 차이 → 수정 HTML | derendering 역방향 | TEDS 수렴 |

핵심 설계 포인트 두 가지를 강조하겠습니다.

- **U1과 U2의 분리가 이 설계의 심장입니다.** 약한 기하(U1)와 강한 의미(U2)를 떼어내, U1만 따로 측정하면 천장이 구조에 있는지 내용에 있는지 즉시 판명됩니다.
- **U3은 모델이 아니라 코드로 합칩니다.** 지난 턴의 "자기회귀 표류"는 모델이 구조와 내용을 동시에 받아쓸 때 생깁니다. 빈 셀 골격(U1)에 내용(U2)을 코드로 끼워 넣으면, 표류가 발생할 자리 자체가 사라집니다.

---

### 측정 도구: TEDS (트리 편집 거리 기반 유사도)

단위를 쪼갰으면 채점표가 필요합니다. 표 변환의 표준 지표는 TEDS (Tree-Edit-Distance-based Similarity)입니다. HTML 표를 트리(tree) 구조로 보고, 정답 트리로 바꾸는 데 드는 최소 편집 횟수로 유사도를 매깁니다. 두 갈래로 씁니다.

- **TEDS-Struct**: 텍스트를 무시하고 골격(행·열·병합)만 채점 → U1 전용. 약점을 정조준합니다.
- **TEDS (full)**: 구조 + 내용 모두 채점 → U3 최종 결과 채점.

이 둘을 분리해 보면 "구조 점수는 높은데 전체 점수가 낮다 → 내용이 문제"처럼 범인이 바로 드러납니다.

여기에 더해 가장 강력한 보조 도구가 **재렌더 시각 대조(round-trip visual diff)**입니다. 생성한 HTML을 다시 이미지로 렌더링해 원본과 나란히 놓으면, 사람도 모델도 "어디가 어긋났는지"를 한눈에 봅니다. 이것이 U4의 원리입니다.

---

### 실험 순서: 절제 사다리 (Ablation Ladder)

이제 무엇부터 시도할지입니다. 한꺼번에 다 넣지 말고, 한 칸씩 올리며 매 칸마다 TEDS를 측정하십시오. 점수 상승폭(delta)이 그 개입의 가치입니다.

```
E0  순진한 단발 ("이 이미지를 HTML로 변환해줘")          ← 기준선(baseline)
E1  + U0 (표 영역만 크롭) + media_resolution 스윕         ← 인식 천장 측정
E2  + 정규화 방지 프롬프트 + thinking_level=high           ← 추측 성향 억제
E3  + U1/U2 분리 (구조 먼저, 내용 나중)                    ← 강/약 축 분리
E4  + U3 코드 조립 (모델 받아쓰기 제거)                    ← 표류 차단
E5  + U4 재렌더 복구 루프                                  ← 잔여 오차 수렴
```

이 사다리의 효용은, 예컨대 E1에서 점수가 크게 오르면 문제의 절반은 단순 해상도였다는 뜻이고, E3에서 폭등하면 진짜 병목은 구조·내용 혼재였다는 결론이 데이터로 확정된다는 점입니다. 추측이 아니라 측정으로 원인을 좁혀갑니다.

### 각 단위의 핵심 기법

#### U0 — 표 영역 격리와 해상도

페이지 전체보다 표 하나만 떼어 입력하면 패치(patch)가 표에 집중되어 골격이 또렷해집니다. media_resolution은 문서는 medium이 최적이고, 글자가 깨질 만큼 작은 표에 한해 high를 테스트하는 식으로 스윕합니다.

#### U1 — 구조만 요청하는 프롬프트 (정규화 방지 포함)

내용을 빼고 골격만 달라고 하면 기하에만 집중시킬 수 있습니다. 동시에 지난 턴의 "그럴듯하게 정리해버리는" 정규화를 막아야 합니다. 막연한 금지("정리하지 마") 대신 한정 지시를 씁니다.

```text
역할: 표 이미지의 구조를 그대로 복원하는 정밀 도구.
출력: 셀 내용은 모두 빈칸으로 두고, <table>의 골격만 HTML로 출력.
규칙:
- 보이는 병합을 rowspan/colspan으로 그대로 표현하라. 격자를 가지런하게 다듬지 마라.
- 표 안의 표가 있으면 <td> 안에 중첩 <table>로 표현하라.
- 보이는 것에만 근거하고, 일반적인 표 형태를 가정해 채우지 마라.
```

`thinking_level`은 여기서 high로 둡니다. 구조 복원은 모델의 약점인 기하 추론이라, 사고 깊이가 가장 필요한 지점입니다.

#### U2 — 행 단위 내용 추출

표류를 더 줄이려면 표 전체가 아니라 행 단위로 끊어 내용을 받습니다. 의미 작업이라 `thinking_level=low`로 비용을 아껴도 충분합니다(질문하기가 성공했던 그 강한 축입니다).

#### U3 — 결정론적 조립

U1의 빈 셀에 U2의 텍스트를 위치 기준으로 끼워 넣습니다. 모델이 개입하지 않으므로 표류가 원천 차단됩니다.

```python
# 골격(U1)의 빈 셀 슬롯에 내용(U2)을 좌표로 매핑해 채움
# 모델 호출 없음 → 자기회귀 표류 0
def assemble(skeleton_html, cell_texts_by_coord):
    ...  # 슬롯 순서대로 텍스트 주입, 누락 슬롯은 경고
```

#### U4 — 재렌더 복구 루프

완성 HTML을 이미지로 렌더링해 원본과 함께 모델에 보여주고 "두 표의 차이만 짚어 수정본을 내라"고 시킵니다. TEDS가 더 오르지 않을 때까지 반복하면 수렴합니다.

### HTML과 MD의 위치 정리

목표가 "온전한 기능"이라면 내부 표준 표현은 HTML로 고정해야 합니다. 디렌더링(derendering)이 지원하는 HTML, LaTeX, Markdown 중 Markdown은 병합·중첩을 적을 문법이 없기 때문입니다. 따라서 MD는 최종 단계의 선택적 내보내기로 두되, **병합·중첩이 없는 평평한 표일 때만** HTML→MD로 변환하는 가드(guard)를 답니다. 복잡한 표를 MD로 강제하는 것은 지난 턴에서 본 "실패가 예정된 작업"입니다.

---

### 최소 실행 버전 (MVP) 제안

처음부터 5단계를 다 만들지 마시고, 다음 순서로 뼈대를 세우길 권합니다.

1. **U1 + TEDS-Struct만 먼저 구현.** 구조 천장을 숫자로 확정합니다. 여기가 안 되면 뒤가 다 무의미합니다.
2. U2를 붙여 full TEDS를 측정.
3. U3 코드 조립으로 표류 제거 효과 확인.
4. 마지막에 U4 루프로 잔여 오차를 긁어냅니다.

---

정리하면, 변환을 "한 번의 번역"이 아니라 **격리·측정·조립·복구의 4박자 공정**으로 재정의하는 것이 핵심입니다. 이렇게 쪼개면 어느 화살표에서 점수가 새는지가 매번 드러나, 감이 아니라 데이터로 기능을 완성해 갈 수 있습니다.

다음으로, 위 단위 중 어디부터 실제 코드로 구현해 드릴까요? 제안드린 대로라면 **U1 구조 추출 + TEDS-Struct 채점기**를 먼저 돌려보는 것이 가장 빠르게 천장을 확인하는 길입니다. 이 한 쌍을 실행 가능한 코드로 짜 드리겠습니다.
